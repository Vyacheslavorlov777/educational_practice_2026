# ER-диаграмма

## Сущности

### 1. partners (Партнёры)

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| partner_id | INTEGER | PK | Уникальный идентификатор партнёра |
| company_name | VARCHAR(255) | | Название компании / ФИО |
| inn | VARCHAR(20) | UNIQUE, NOT NULL | ИНН партнёра |
| contact_email | VARCHAR(255) | | Email для связи |
| phone | VARCHAR(50) | | Телефон (может отсутствовать) |
| rating | NUMERIC(3,1) | | Рейтинг партнёра (может отсутствовать) |

### 2. products (Товары)

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| product_id | INTEGER | PK | Уникальный идентификатор товара |
| product_name | VARCHAR(255) | UNIQUE, NOT NULL | Название товара |

Товар вынесен в отдельную таблицу, потому что одно и то же название товара
встречается в нескольких отгрузках. Хранить название товара прямо в таблице
продаж — значит дублировать данные и нарушать 3NF (транзитивная зависимость
названия товара от продажи вместо хранения в отдельной сущности).

### 3. shipments (Отгрузки / продажи)

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| sale_id | INTEGER | PK | Уникальный идентификатор отгрузки |
| partner_id | INTEGER | FK → partners.partner_id | Партнёр, которому отгружен товар |
| product_id | INTEGER | FK → products.product_id | Отгруженный товар |
| sale_date | DATE | NOT NULL | Дата отгрузки (формат YYYY-MM-DD) |
| quantity | INTEGER | NOT NULL | Количество товара |
| total_amount | NUMERIC(12,2) | NOT NULL | Сумма отгрузки |

## Связи

```
partners (1) ────< (N) shipments (N) >──── (1) products
```

* Один партнёр может иметь много отгрузок (1 : N).
* Один товар может встречаться во многих отгрузках (1 : N).
* Таблица `shipments` хранит связь партнёр ↔ товар как отдельная запись отгрузки.

## Проверка нормальных форм

* **1NF** — все поля атомарны, повторяющихся групп и массивов нет.
* **2NF** — первичные ключи всех таблиц простые (не составные), поэтому
  частичных зависимостей быть не может.
* **3NF** — название товара вынесено из `shipments` в `products`, поэтому
  неключевые поля `shipments` (дата, количество, сумма) зависят только от
  `sale_id` и не зависят друг от друга.

## Текстовая схема (для генерации PNG)

```
+------------------+        +------------------+        +------------------+
|    partners      |        |    shipments      |        |     products     |
+------------------+        +------------------+        +------------------+
| PK partner_id    |<-------| FK partner_id     |------->| PK product_id    |
|    company_name  |   1  N | FK product_id      | N   1  |    product_name  |
|    inn           |        | PK sale_id         |        +------------------+
|    contact_email |        |    sale_date       |
|    phone         |        |    quantity        |
|    rating        |        |    total_amount    |
+------------------+        +------------------+
```
