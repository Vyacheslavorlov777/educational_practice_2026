# Задание 3. Подготовка данных и импорт (ETL)

## Исходные файлы

* `import_partners.csv` — список партнёров (CSV, разделитель `,`).
* `import_sales.txt` — список продаж (TSV, разделитель табуляция).

Оба файла скопированы в эту папку без изменений.

## Найденные проблемы

1. **Лишние пробелы** в `company_name` (например, `" ООО \"Логистик-Экспресс\" "`).
2. **Разные форматы дат** в `sale_date`: `2026-03-01` (ISO) и `15.03.2026` (DD.MM.YYYY).
3. **Отсутствующий партнёр**: продажа `sale_id=104` ссылается на `partner_id=4`,
   которого нет в `import_partners.csv`.
4. **Пустые необязательные поля**: `phone` у партнёра 2 и `rating` у партнёра 3.
5. **Повторяющиеся названия товаров**: «Стиральный порошок "Альфа"» и
   «Мыло жидкое "Стандарт"» встречаются в нескольких продажах — вынесены в
   отдельную таблицу `products`.

## Выполненные преобразования

* Убраны лишние пробелы вокруг `company_name`.
* Дата `15.03.2026` приведена к формату `2026-03-15` (YYYY-MM-DD).
* Пустые значения `phone` и `rating` сохранены как `NULL`, а не как выдуманные данные.
* Из товаров выделены уникальные названия в отдельную сущность `products`.

## Обработка отсутствующего partner_id

Продажа `sale_id=104` (`partner_id=4`) **не загружается** в `shipments`,
потому что партнёра с `partner_id=4` нет в таблице `partners`. Загрузка этой
записи нарушила бы `FOREIGN KEY`. Запись исключена из `cleaned_sales.csv` и
зафиксирована как проблема качества исходных данных здесь, в README.
Как только в системе появится партнёр с `partner_id=4`, эту продажу можно
будет загрузить отдельно.

## Какие данные загружаются в каждую таблицу

* `partners` — из `cleaned_partners.csv`, все 3 записи.
* `products` — уникальные названия товаров из `cleaned_sales.csv` (3 товара).
* `shipments` — из `cleaned_sales.csv`, 4 записи (без `sale_id=104`).
